## 2. What's built

- **Canvas & build mode**: place Bouncer/Trigger/Spawner/Peg field via toolbar, drag/rotate/resize (single corner handle for square → independent width/height), alt-drag to duplicate, `+` badge opens the popover.
- **Multi-select**: drag on empty canvas to marquee-select a rect of objects live as you drag; shift-drag adds to the existing selection, shift-click toggles a single object; dragging any object that's part of a multi-selection moves the whole group together. Backspace/Delete removes every selected object in one undo step.
- **Peg field**: drag/resize/rotate like a square, pegs auto-populate a hex grid from spacing + field size. Sound is field-level (`field.sound`, not `obj.sound`) and shared by every peg (all pegs share the field object's own id, so any hit routes to the same gate/pitch state). "Field pitch" (Up/Down/Left→Right/Right→Left/Random) replaces the normal Pitch selector — the struck peg's own position, normalized against the field's *own* (rotation-aware) local bounds, scales onto Range.
- **Play mode + Pause**: mode toggle + separate Pause button, defaults paused on load so a freshly-placed object never immediately sounds.
- **Object model**: one generic object, composable `physics`/`sound`/`spawn` modules, presets are just factories with different starting values. `src/state/object.js` is the source of truth for the current shape.
- **Generators**: prime, fibonacci, markov, lfsr, wolfram, euclidean, plus `none` and `manual` (hand-toggled step grid), unified through `generators/gate.js`'s `evaluateGate`. Manual resolution is a note-subdivision scaled by the spawner's numerator, not a fixed grid size.
- **Global BPM**; time signature (numerator/denominator, independently driftable) stays per-spawner.
- **Key/mode**: global note+octave+mode, with a per-object override — note/octave/mode are each independently overridable (overriding just the octave, say, no longer requires also overriding note).
- **Accent gate**: second hit-indexed gate per sound module, fires only on notes the main gate already passed, swaps in an alternate pitch instead of adding a note. Off by default (opt-in). Phase-locked to the main gate's own hit-index (`generators/gate.js`'s `evaluateGateAt`) — it used to run its own separately-incrementing "how many accented notes have I seen" counter, which meant picking the same step number in both grids didn't actually land on the same note (the two counters drifted out of phase since the accent only advanced on the subset of hits the main gate let through). Fixed a prior session.
- **Gate hit-counter bug, found and fixed this session**: `evaluateGate` returned early for a null-type ("Always on") main gate *without* incrementing `gate.index` — since that index doubles as the hit counter the accent gate phase-locks to, leaving the main Gate at its default "Always on" pinned every hit to index 0 forever. In practice: a manual accent pattern only ever matched its first step (always fires if step 0 is selected, never fires otherwise), and prime/markov/etc accent generators only ever read their very first table/RNG value. Root-caused from the user's own repro (spawner → trigger, melody, gate always-on, accent manual pattern on the last step only) and fixed in [gate.js](src/generators/gate.js) — the null branch now advances the counter like every other gate type. Two regression tests added in `generators.test.js`.
- **Particles are real objects**: each spawned particle gets its own cloned sound module with a live, independently-accumulating gate. Can opt out of sound entirely (pure exciter) via `particlesHaveSound`.
- **Spawner Collide toggle**: whether the spawner has a physics body at all — on (default) means freshly-spawned particles sound immediately ("sound on spawn"); off means silent until they hit something else.
- **Pitch behaviors** (per sound-carrying object): Fixed / Random / Cycle-up / Cycle-down / **Piano**. `Positional` exists internally for peg fields but isn't offered in the general dropdown (only meaningful with a live position peg fields supply programmatically).
- **Piano**: a continuous 3-octave (36-key) widget in the popover, root at the leftmost key. Notes stored as semitone offsets from the object's own effective root — root/octave changes transpose every picked note for free (nothing stored needs to change); a mode change snaps any now-out-of-scale pick to its nearest in-scale neighbor (the one place in the app where a settings change reaches back in and rewrites object data, wired through `canvasState.js`'s `notify()` so every path — global key, per-object override, project load, undo/redo — is caught uniformly). Own "Cycle" order (Up/Down/Up-down/Down-up/Random). Empty selection plays nothing. Chord (pad) and Accent both build on Piano's resolved root exactly like they do for every other pitch behavior — Accent reuses the main pitch's picked notes, no second widget.
- **Six voices**: kick, snare, hat, bass, pad, melody. Pad's Chord toggle only decides whether extra chord tones stack on the root — the root itself always follows whatever Pitch behavior is selected, regardless of Chord state.
- **Global per-instrument sound design** (system menu, Instruments cards): kick/snare/hat share a 3-knob baseline (Decay/Tone/Pitch); bass/pad/melody get a deeper tier — a full ADSR-shaped amplitude envelope (Attack/Decay/Sustain level/Sustain time/Release, replacing the old single Decay knob this session), tone, waveform, resonance, filter envelope, unison, vibrato, noise transient, and — bass only — a sub oscillator. The old duplicate octave/pitch knob (redundant with per-object key-override) was removed this session too. Deliberately global-only, not per-object. `sustainTime` exists because every note here is a one-shot physics-triggered hit, not a held key — there's no real note-off for a normal ADSR's Sustain stage to release against, so Attack→Decay ramps to Sustain level, holds there for `sustainTime` seconds (0 default = a plain "plonk," identical to the prior sound), then Release fades out; raising `sustainTime` is how you fake a longer, held-feeling note. **Play-tested and confirmed working** — see §6 for fine-tuning notes still to come.
- **Reverb/delay return buses**, per-object send amounts.
- **Output limiter**: a `DynamicsCompressorNode` after the master bus, on by default (ceiling −3dB). System-menu card (Enabled + Ceiling) with an at-your-own-risk warning; disabling sets the compressor to a true 1:1 bypass rather than disconnecting the graph.
- **Undo/redo**: 50-step snapshot buffer, menu buttons plus Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z.
- **Persistence**: localStorage project manager (save/open/save-as/delete/rename), JSON export/import.
- **Palette**: cream + 6 pastels, editable, applied via CSS custom properties; every new object gets a random pastel.
- **Default sizes per object class** (system menu) — a freshly-placed object picks up whatever's currently configured; only affects objects placed after the change.
- **System menu**: wide top-anchored sheet, two side-by-side islands — Instruments (left, nearest the hamburger) and Global (right: undo/redo, project, timing, key/mode, physics, limiter, default sizes, palette, JSON) — each a CSS-multi-column masonry card grid.
- **Spawner timing**: edge-triggered, no catch-up/replay mechanism — each tick computes "which step is this, right now" by division and fires at most once if that differs from the last-fired step. Deliberate trade: at BPM/subdivision combos faster than one rendered frame, firing rate silently caps at one particle/frame instead of staying locked to tempo — chosen because a burst (the old failure mode) is worse than a very-slightly-under-tempo edge case.
- **ES-9 hardware output**: built this session, end to end (routing UI, dedicated AudioContext, channel lanes, voice-stealing/glide, mute layers) — see §5 for the full writeup. **User-tested against real hardware this session and confirmed working.**
- **Pan/zoom canvas + object cap**: see prototype.md §16 for the full writeup. Camera is a fixed, generous, finite world rect (`render/camera.js`'s `WORLD`), not infinite; pan via space+drag/middle-click-drag/trackpad two-finger scroll, zoom via ctrl/cmd+scroll centered on the pointer. A live physics-body counter (plain text) sits next to the toolbar's Peg field button (pegs count individually); an optional hard object cap (off by default, its own card) silently blocks new spawner particles once the live count reaches it, turning the counter red at that point. **User-tested and confirmed operational.** Note: the cap's body-count metric is a proxy, not the real bottleneck — see §3, the audio graph, not physics/rendering, is what actually chokes at high concurrency.

## 3. Known gaps / open items

- **Rotated-rect hit-testing/resize wrinkle**: for any rect-shaped object (`square`, peg fields), clicking near a visually-rotated corner or dragging its resize handle is measured against an unrotated (axis-aligned) bounding box — physics itself rotates the actual body correctly, only the on-canvas interaction math doesn't account for tilt. **User-confirmed click-only** — it never affected physics (bodies always collided/rotated correctly), only the on-canvas click/drag hit-test. Tested and not an issue in practice; deprioritized, not worth fixing further.
- **High concurrent audio voice count, not object/body count, is the real ceiling** — a dense-but-spread-out peg field handles 4000+ live bodies fine, but particles funneled through few sound-producing objects can choke the audio graph around ~125 concurrent. The object cap (§2, prototype.md §16) is a body-count proxy failsafe for this, not a direct fix — a real concurrent-voice throttle isn't built.

## 5. ES-9 hardware output — built and user-tested against real hardware

A previous session built a browser-to-ES-9 (Expert Sleepers ES-9 Eurorack interface) test page, sending pitch/gate CV over USB via multichannel WebAudio — **not MIDI**, an earlier version of this doc had that wrong. That file (the original `index.html`, an "ES-9 CV/Gate Test Rig") was accidentally destroyed in a later session's file-rename mistake — see `architecture.md` §2 for where the current `index.html` came from instead. The user rebuilt/restored it outside this repo and it now lives here as `test.html`: `ConstantSourceNode`s for pitch (1V/oct DC offset) and gate (on/off DC level) feeding a 16-channel `ChannelMergerNode`, routed to the ES-9 via `AudioContext.setSinkId`. Only 8 of the ES-9's 16 device channels (its DC-coupled 3.5mm Eurorack jacks) are usable this way.

**Strategy pass (this session) — resolved, see prototype.md §15 for the full writeup**:
- ES-9 output runs on its **own dedicated AudioContext**, fully separate from the app's normal listening context.
- Routing lives **inside each object's sound module** (requires a sound module — no bare-physics-object routing yet). Any number of **lines** per object, each a channel (1–8) + signal type: **pitch** (1V/oct), **gate** (high through the object's own internal ADSR's Attack→Decay→Sustain-hold, low at Release — reuses existing ADSR knobs, no new gate-length control), **adsr** (same envelope as shaped CV, *replaces* gate rather than adding a 3rd out — a note only ever costs 2 outs), **audiosignal** (the object's real audio, at audio rate — this *does* replace that object's local app playback; the other three signal types don't).
- **Channels are not exclusive** — routing multiple objects to one channel is intentional (patch-cable-stacking mental model), not prevented. The ES-9 settings card shows an "x/8 channels patched" readout.
- **Voice stealing**: each channel is monophonic in practice; whichever object last triggered a note on a channel takes it over. **Legato/staccato/auto-glide (+ glide time) is a per-object setting** — the winning (stealing) object's own setting applies. Auto-glide (303-style): glide+legato if the previous note on that channel is still gated/enveloping when the new one fires, otherwise staccato.
- **Calibration is global** (full-scale volts, gate-high volts, root note) — one interface, one calibration, not per-channel.
- **Three independent mute layers**, next to the mode toggle (relabeled **Clean**, was Play): Pause (existing, freezes physics/spawning — not for performance use, desyncs timing); **Mute Unsent** (mutes the app's own local AudioContext only — ES-9 output keeps going; since audiosignal-routed objects never play locally anyway, this is just "mute the whole app context," no per-object logic); **Mute All** (mutes both contexts, full silence, but keeps physics/spawning/scheduling running so un-muting doesn't desync).
- Module layout: `es9/context.js` (device connection, calibration, the 8 persistent per-channel `ConstantSourceNode` lanes), `es9/routing.js` (per-object routing, voice-stealing/glide decision, gate/adsr scheduling, the simplified audiosignal oscillator voice, `patchedChannelSummary` for the "x/8" readout) — see `architecture.md`. No separate `sync.js` ended up needed: unlike physics bodies, a channel lane isn't owned by any one object, so there's nothing per-object to build/rebuild — stuck-voltage safety (`allChannelsLow`) is just called directly from `main.js`'s Pause and Mute All handlers instead.

**Implemented, this session**:
- `state/object.js`: `Es9Module` (`enabled`, `lines: {channel, signal}[]`, `glideMode`, `glideTime`) nested in every `SoundModule` via `createEs9Module()`.
- `es9/context.js`: dedicated `AudioContext`, device scan/connect/disconnect (`setSinkId`, same shape as `test.html`), 8 channel lanes, calibration (`fsVolts`/`gateVolts`/`rootMidi`), `setEs9Muted`, `allChannelsLow`.
- `es9/routing.js`: `triggerEs9(sound, effectiveKey, opts)` called from `main.js`'s `onHit` right alongside `scheduleNote` — pitch/gate/adsr write to the shared channel lanes (monophonic voice-stealing, glide decided by `decideGlide`), `audiosignal` gets its own lightweight oscillator+envelope voice connected straight into the ES-9 merger and reports `suppressLocal: true` so `main.js` skips the normal `scheduleNote` call for that hit. Gate/adsr duration reuses the object's own instrument ADSR (`gateHighSeconds`) rather than a new control.
- `audio/context.js` + `es9/context.js`: independent mute gains for Mute Unsent (app context only) and Mute All (both), wired to new `canvasState` getters/setters (`getMuteUnsent`/`getMuteAll`/etc, same ephemeral-not-serialized pattern as `paused`).
- `ui/objectPopover.js`: an "ES-9 out" subsection inside every sound module's fields (works uniformly for a plain object's `sound`, a peg field's `field.sound`, a spawner's `spawn.particleSound`) — enable toggle, per-line channel+signal pickers with add/remove, glide mode + glide time. Column labels ("Channel"/"Signal") show once above the stack, not repeated per line, per later feedback — space in the popover is tight enough that a 3+ line object was getting noticeably tall.
- `ui/systemMenu.js`: an "ES-9" card in the Instruments grid (space, not category — see below) — connect flow, calibration fields, "x/8 channels patched" readout. `main.js` now re-renders the system menu once whenever the hamburger opens (not continuously) so this stays fresh without paying a full-menu DOM rebuild on every physics-frame `notify()`.
- `index.html`/`main.js`: Mute Unsent / Mute All icon buttons next to the mode toggle; mode toggle now labeled **Clean** (was unlabeled, tooltip said "Play").
- `test/es9.test.js`: the pure decision logic — `decideGlide`, `gateHighSeconds`, `pitchToUnit`, `patchedChannelSummary` — plus `Es9Module`/`SoundModule` defaults. `node --check` clean on every touched file (full suite status: §1).

**Known simplification**: `audiosignal` routing does not reuse the actual kick/snare/bass/pad/melody voice modules (those are wired only to the app's own listening context) — it's a separate, simpler oscillator+ADSR-shaped-envelope voice in `es9/routing.js`, using the object's resolved pitch and instrument settings (waveform/attack/decay/sustain/release) but not each voice's own unison/filter-sweep/sub-oscillator/etc character. Good enough to get real audio out to the modular; revisit if a specific voice's exact timbre needs to reach the ES-9 out too.

**Not yet decided / worth revisiting once played with**: whether a purely physical (no sound module) object should ever be able to fire a bare ES-9 gate; per-channel calibration if a specific module ever needs non-1V/oct scaling.

## 7. Next session — open-sourcing the repo + persistent settings

Raised at handoff, not started. Two related but separate goals:

**A. Turn this into a real, shareable git repo.** Currently no `.git`, no README, no LICENSE, no `.gitignore` — `package.json` is even still marked `"private": true`. Goal is friends being able to clone/fork and bend it into whatever shape they like, so next session needs: `git init` + an initial commit, a README (what this is, how to run it — `python3 -m http.server 8934` — how to test — `npm test` — and a pointer to prototype.md/architecture.md/handoff.md for anyone diving into the code), a LICENSE (**not chosen yet — the user's call**; MIT is the obvious default for "clone and do whatever" intent but shouldn't be assumed), and a minimal `.gitignore` (no build step, nothing generated to ignore yet beyond the obvious OS cruft). Pushing to a public remote (GitHub, presumably) is the actual "online" step, and — per this app's own safety rules — that's a publishing action visible to others, worth confirming explicitly with the user before it happens rather than doing on momentum once the repo's in shape locally.

**B. Global settings/defaults should survive a reload on their own, without an explicit save.** Right now `persistence/localProject.js` only ever persists anything when the user explicitly Saves/Opens a named project (prototype.md §10) — a plain page reload always resets to `canvasState.js`'s hardcoded module-level defaults (per-class object defaults, palette, physics settings including the object cap, instrument sound design, limiter, global key/mode). These are already adjustable per session (system menu) but the tuning is lost on the next visit unless the user remembers to save a project purely to preserve settings, not because they wanted to save a patch. Fix: a separate, automatic localStorage layer distinct from the named-project store, that persists just the "studio settings" (not the actual canvas/objects) and silently restores them on load — `canvasState.js`'s existing `serialize()` already has close to the right shape to draw from (everything except `objects`). A debounced auto-save-on-change plus a load-on-init pass is the likely shape; worth a session's dedicated attention rather than bolting on quickly.

**Open question for the user, next session**: should this auto-restore extend to the actual canvas layout too (continue exactly where you left off, like most browser apps), or should settings/defaults be the only thing that's ambient while canvas layout stays a deliberate, explicit "project" you save on purpose? The user only asked for "settings and defaults" here — treating canvas objects as out of scope for auto-persistence unless told otherwise.
